# 🛠️ 트러블슈팅 로그 (Troubleshooting Log)

본 문서는 개발 과정에서 발생한 기술적 문제와 그 해결 과정을 기록합니다. 단순한 오류 수정을 넘어, 문제의 근본 원인을 파악하고 재발 방지 대책을 세우는 과정을 통해 엔지니어링 역량을 강화하는 데 목적이 있습니다.

---

## 📝 로그 기록 형식 (Template)
- **ID:** #ERR-00x
- **일시:** YYYY-MM-DD
- **문제 발생 상황 (Context):** 어떤 기능을 구현하던 중이었는가?
- **오류 현상 (Symptoms):** 화면 에러, 콘솔 로그, 서버 로그 등
- **원인 분석 (Root Cause):** 왜 이런 일이 발생했는가?
- **해결 과정 (Resolution):** 어떻게 수정했는가? (코드 포함)
- **교훈 및 인사이트 (Takeaways):** 이 문제를 통해 무엇을 배웠는가?

## 🚀 해결된 문제 목록

### #ERR-001: ORM 결과 객체 참조 오류
- **일시:** 2026-04-23
- **문제 상황:** 상세 페이지(`read_book`) 로직 구현 중 DB에서 책 정보를 가져와 템플릿으로 전달함.
- **오류 현상:** Jinja2 템플릿에서 `book.title` 등을 읽으려 할 때 속성을 찾을 수 없거나 출력이 안 됨.
- **원인 분석:** SQLAlchemy의 `db.execute(stmt)`는 `CursorResult` 객체를 반환하며, 이는 실제 데이터 행(Row)이 아니므로 바로 모델 속성에 접근할 수 없음.
- **해결 과정:** `crud.py`에서 결과를 반환할 때 `.scalar_one_or_none()`을 사용하여 실제 모델 인스턴스(객체) 하나를 반환하도록 수정.
- **인사이트:** ORM을 사용할 때는 쿼리 실행 결과가 '목록(List)'인지, '단일 객체(Object)'인지, 아니면 '실행 상태(Result)'인지 명확히 구분해야 함.

### #ERR-002: 정적 JS 파일 내 Jinja2 문법 사용 불가
- **일시:** 2026-04-23
- **문제 상황:** `book_detail.js` 파일 내에서 현재 책의 ID를 사용하기 위해 `fetch("/books/{{ book.id }}/reviews")` 사용.
- **오류 현상:** 404 에러 발생. 브라우저가 `{{ book.id }}`라는 문자열을 그대로 URL로 인식함.
- **원인 분석:** Jinja2는 `.html` 파일만 렌더링하며, `static/`에 담긴 `.js` 파일은 서버가 건드리지 않고 브라우저에 그대로 전달함.
- **해결 과정:** 
    1. HTML 태그에 `data-book-id="{{ book.id }}"` 형식으로 데이터를 심어둠.
    2. JS에서 `Element.dataset.bookId`를 통해 값을 읽어와 URL을 동적으로 생성함.
- **인사이트:** 서버 사이드 렌더링(SSR) 변수와 클라이언트 사이드 스크립트(JS) 간의 데이터 전달은 HTML 요소를 매개체(Dataset 등)로 활용하는 것이 표준적인 방법임.

### #ERR-003: DOM 요소 참조 Null 에러 (비동기 렌더링 충돌)
- **일시:** 2026-04-23
- **문제 상황:** 리뷰 목록 바구니에 리뷰 데이터를 채우려 함.
- **오류 현상:** `Uncaught TypeError: Cannot set properties of null (setting 'innerHTML')`
- **원인 분석:** `id="review-list"` 요소가 드래프트 상태(리뷰가 없을 때)에서 `{% if %}` 문 안에 갇혀 있어, JS가 실행될 시점에 DOM에 존재하지 않음.
- **해결 과정:** 
    1. 리뷰 컨테이너를 `if` 바깥으로 빼서 항상 존재하게 함.
    2. 데이터 유무에 따른 메시지 처리는 컨테이너 내부 내용물이나 JS CSS 제어(`display: none`)로 해결함.
- **인사이트:** 비동기 작업을 위한 DOM 조작 시, 해당 요소가 조건부로 생성되는지 여부를 항상 확인해야 하며, 안정성을 위해 '고정된 컨테이너'를 확보하는 것이 유리함.

### #ERR-004: 포트 충돌로 인한 서버 접속 불가 (Address already in use)
- **일시:** 2026-04-26
- **문제 상황:** 예외 처리 코드를 수정한 후 브라우저에서 `localhost:8000` 접속을 시도함.
- **오류 현상:** 브라우저에서 `ERR_CONNECTION_REFUSED` 표시. 서버를 재시작하려 하면 터미널에 `ERROR: [Errno 98] Address already in use` 출력.
- **원인 분석:** 이전에 실행했던 `uvicorn` 프로세스가 완전히 종료되지 않은 채 포트 8000을 계속 점유하고 있었음. `--reload` 모드에서 코드 오류 발생 시 리로더 프로세스는 살아있지만 실제 서버 프로세스는 죽는 '좀비 프로세스' 상태가 발생할 수 있음.
- **해결 과정:** 
    1. `lsof -i :8000`으로 포트를 점유 중인 프로세스 PID를 확인.
    2. `kill -9 $(lsof -t -i:8000)`으로 해당 프로세스를 강제 종료.
    3. 가상환경 활성화 후 서버를 재시작하여 정상 접속 확인.
- **인사이트:** 
    1. 개발 중 서버가 비정상 종료되면 포트가 점유된 채 남을 수 있으므로, `lsof -i :포트번호` 명령어를 습관적으로 확인하는 것이 좋다.
    2. `fuser -k 8000/tcp` 명령어도 같은 역할을 수행하며 더 간결하다.
    3. WSL2 환경에서는 `--host 0.0.0.0` 옵션을 주어야 윈도우 호스트 브라우저에서 접속 가능한 경우가 있다.

### #ERR-005: SQLite DB 스키마 불일치 에러 (OperationalError)
- **일시:** 2026-04-29
- **문제 상황:** `models.py`에 도서 상세 정보(출판사, 출판연도 등)를 위한 새로운 컬럼을 추가하고 앱을 구동하여 검색 기능을 사용함.
- **오류 현상:** `500 Internal Server Error` 발생. 서버 로그에 `sqlite3.OperationalError: no such column: books.publisher` 기록됨.
- **원인 분석:** SQLAlchemy의 `Base.metadata.create_all` 메서드는 애플리케이션 시작 시 DB 파일(`sql_app.db`)이 존재하지 않을 때만 테이블을 생성함. 기존에 생성된 테이블에 변경 사항(추가된 컬럼)이 있을 경우 이를 자동으로 반영(Migration)해 주지 않기 때문에, 코드에서 존재하지 않는 컬럼을 참조하려다 에러가 발생한 것임.
- **해결 과정:**
    1. 개발 초기(MVP) 단계이므로 가장 신속한 방법인 기존 `sql_app.db` 파일을 삭제(`rm sql_app.db`)함.
    2. 앱을 재기동하여 새로운 스키마 모델에 기반한 테이블을 새롭게 생성함으로써 문제 해결.
- **인사이트:**
    1. ORM을 통한 모델 편의성은 높지만, 스키마 변경 시에는 DB 엔진 자체의 동기화가 필요하다는 점을 인지해야 함.
    2. 프로젝트가 상용화 수준에 이르면 데이터 유실 방지를 위해 DB 마이그레이션 도구(예: Alembic)를 필수적으로 도입해야 함.

### #ERR-006: Yes24 검색 시 메인 페이지로 리다이렉트 (Header Paradox)
- **일시:** 2026-05-12
- **문제 상황:** `fetch_yes24_goods_id` 함수에서 ISBN으로 Yes24 검색 결과를 가져오려 함.
- **오류 현상:** `requests.get`으로 검색 URL을 호출하면 검색 결과 대신 메인 페이지(`/Main/default.aspx`)의 HTML이 반환됨. `print(soup)`으로 확인 시 메인 페이지의 공지사항, 베스트셀러 등이 출력됨.
- **원인 분석:** `User-Agent`를 Chrome 브라우저로 설정했으나, 실제 브라우저가 기본으로 보내는 다른 복잡한 헤더들(`Sec-Ch-Ua`, `Accept-Encoding` 등)이 누락됨. Yes24 WAF(웹 방화벽)가 이를 "어설프게 브라우저인 척 하는 봇"으로 판단하여 302 리다이렉트로 메인 페이지로 튕겨냄.
- **해결 과정:**
    1. Insomnia에서 동일 URL을 테스트하여 검색 결과가 정상 반환되는 것을 확인.
    2. 헤더를 제거하고 `requests` 라이브러리 기본값(`python-requests/2.X.X`)으로 요청한 결과 정상 작동.
    3. `User-Agent` 헤더 관련 코드를 주석 처리하여 해결.
- **인사이트:**
    1. 크롤링 시 헤더 전략은 "없음 → 기본 → 브라우저 전체 → 세션 유지" 순서로 테스트하여 가장 잘 작동하는 조합을 찾아야 함.
    2. 브라우저인 척 하려면 `User-Agent`뿐 아니라 `Accept`, `Sec-Ch-Ua` 등 **전체 헤더 세트**를 완벽하게 흉내 내야 하며, 일부만 넣으면 오히려 역효과가 날 수 있음.
    3. 사이트마다 봇 감지 전략이 다르므로, 교보문고(헤더 필요)와 Yes24(헤더 제거)처럼 각 사이트에 맞는 전략을 개별 관리해야 함.

### #ERR-007: BeautifulSoup `KeyError: 'class'`
- **일시:** 2026-05-12
- **문제 상황:** Yes24 검색 결과 HTML에서 `gd_name` 클래스를 가진 `<a>` 태그를 찾으려 함.
- **오류 현상:** `if "gd_name" in a_tag["class"]:` 실행 시 `KeyError: 'class'` 발생.
- **원인 분석:** `soup.find_all("a", href=True)`로 가져온 모든 `<a>` 태그 중 `class` 속성이 없는 태그가 존재함. 딕셔너리 `[]` 접근은 키가 없으면 `KeyError`를 발생시킴.
- **해결 과정:**
    1. `soup.find_all("a", class_="gd_name")`으로 변경하여 검색 시점에 필터링.
    2. 또는 `a_tag.get("class", [])`로 안전하게 접근하는 방법도 가능.
- **인사이트:** BeautifulSoup에서 태그 속성에 접근할 때는 `tag["attr"]` 대신 `tag.get("attr", default)` 패턴을 사용하거나, `find_all`의 파라미터로 미리 필터링하는 것이 안전함.
