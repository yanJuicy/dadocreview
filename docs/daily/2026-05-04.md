## 📋 오늘의 작업 흐름 (Overview)

1. **워밍업 퀴즈**: Pandas, SQLAlchemy, localStorage 등 지난 세션 복습 완료.
2. **"나의 도서관" UI 구현**: `index.html`에 도서관 검색 모달 및 뱃지 UI 추가.
3. **데이터 정합성 이슈 발견**: 
   - 천안시 청수도서관 등 사용자가 실제로 이용하는 도서관이 공공 데이터셋(Excel) 및 정보나루 API에 누락된 것을 확인.
   - 정보나루 통계 확인 결과, 전국 공공도서관의 약 86%만 참여 중이며 충남 지역은 약 74% 수준임을 파악.
4. **전략적 피벗(Pivot)**:
   - 모든 도서관을 API로만 처리하기에는 데이터 파편화가 심각하다고 판단.
   - '나의 도서관' 기능을 완벽하게 구현하기 위해서는 **직접 등록 기능** 및 **개별 도서관 스크래퍼** 도입이 필수적임.
   - 현재 단계에서는 핵심 기능(도서 리뷰 요약 등)에 집중하기 위해 도서관 연동은 후순위로 미룸.
5. **코드 원복**: 오늘 작업한 모든 실험적 코드를 지우고 문서로 교훈을 정리함.

## 🔍 핵심 인사이트: 공공 데이터의 한계와 해결 방안

### 1. 문제 상황
- '천안시립청수도서관'처럼 실제 운영 중인 도서관이 중앙 API 시스템에 등록되지 않아 검색이 불가능함.
- 사용자는 본인의 단골 도서관 정보를 얻지 못해 서비스의 효용성이 떨어짐.

### 2. 해결을 위한 설계 제안 (Future Work)
- **Hybrid Search**: 로컬 DB + 실시간 API + 사용자 직접 입력의 3단계 구조.
- **Graceful Degradation**: API 연동이 안 되는 도서관은 대출 가능 여부 대신 '홈페이지 바로가기' 링크를 제공하여 사용자 경험을 유지.
- **Custom Scrapers**: 주요 미지원 도서관에 대해서는 해당 도서관 웹사이트를 직접 크롤링하는 전용 스크래퍼 구축.
