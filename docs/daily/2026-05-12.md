## 1️⃣ 주요 구현 내용

### A. Yes24 상품 ID 추출 (`fetch_yes24_goods_id`)
- ISBN을 쿼리로 Yes24 PC 검색 페이지(`/product/search`)에 요청하여, `class="gd_name"`인 `<a>` 태그에서 상품 ID(`goodsNo`)를 추출하는 로직 구현.
- **핵심 발견:** `User-Agent` 헤더를 넣으면 오히려 메인 페이지로 리다이렉트되고, 헤더 없이(기본값) 요청하면 정상 작동하는 현상 확인 → **Header Paradox** (아래 트러블슈팅 참조).
- 검증 ISBN: `9788925588735` (프로젝트 헤일메리) → 상품 ID `101375755` 정상 추출 확인.

### B. 모바일 리뷰 엔드포인트 분석
- **리뷰 목록 URL**: `https://m.yes24.com/Goods/ReviewList/{goods_id}?pageSize=10&pageNumber=1&sort_tp=2`
- **리뷰 HTML 구조 분석 완료:**
  - 리뷰 컨테이너: `<div class="revwSet" data-review-seq="...">`
  - 평점: `<span class="total_rating total_rating_10">` (클래스명에서 10점 만점 숫자 추출)
  - 내용: `<div class="revwCont">` 내부의 텍스트
  - 제목: `<div class="topTit">` 내부의 텍스트
- 11개 리뷰 아이템 탐지 성공 확인.

## 2️⃣ 트러블슈팅 (Troubleshooting)

### # Yes24 Header Paradox (봇 감지 리다이렉트)
- **현상:** `User-Agent`를 Chrome 브라우저로 설정하면 302 리다이렉트 → 메인 페이지(`/Main/default.aspx`)로 이동. 헤더를 비우면 검색 결과 정상 반환.
- **원인 분석:** Yes24 WAF(웹 방화벽)가 `User-Agent`만 있고 다른 브라우저 고유 헤더(Sec-Ch-Ua, Accept-Encoding 등)가 없는 "어설픈 브라우저 흉내" 요청을 봇으로 판단하여 차단. 반면 `python-requests` 기본 헤더는 단순 라이브러리 요청으로 분류되어 통과.
- **해결:** 헤더를 제거하고 `requests` 기본값으로 요청. 향후 차단 시 모바일 검색 URL로 전환하는 예비 전략 보유.
- **교훈:** 크롤링 시 헤더 전략은 [헤더 없음 → 기본 → 브라우저 전체 → 세션 유지] 순서로 테스트하여 가장 잘 작동하는 조합을 찾아야 함.

### # BeautifulSoup `KeyError: 'class'`
- **현상:** `a_tag["class"]`로 클래스를 확인하려 할 때 `KeyError` 발생.
- **원인:** 모든 `<a>` 태그에 `class` 속성이 있는 것은 아님. 속성이 없는 태그에 `[]`로 접근하면 에러.
- **해결:** `soup.find_all("a", class_="gd_name")`으로 검색 시점에 필터링하거나, `a_tag.get("class", [])`로 안전하게 접근.
