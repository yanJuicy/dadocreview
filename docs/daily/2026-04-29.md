## 1️⃣ 주요 구현 내용

### A. 핵심 기능: 검색 결과 페이지네이션
- **Naru API 연동:** `fetch_books_from_naru` 함수에 `page_no`, `page_size` 파라미터를 추가하여 Naru API의 페이지네이션 기능 지원.
- **DB 로직:** `search_books_by_title` 함수에 `limit`, `offset`을 적용하여 필요한 만큼의 데이터만 DB에서 조회하도록 SQL 최적화.
- **UI 적용:** `results.html` 하단에 사용자 친화적인 [이전], [다음] 버튼과 현재 페이지 표시 로직(Jinja2) 추가.

### B. 데이터 모델 고도화: 도서 상세 정보 확장
- 정보나루 API의 응답 데이터에서 `publisher`, `publication_year`, `loan_count` 필드를 추가로 정제(Refining) 및 파싱.
- SQLAlchemy 모델(`models.py`)과 Pydantic 스키마(`schemas.py`)에 새로운 컬럼(필드)을 추가하여 API-DB 간의 구조적 불일치 해소.
- `app/crud.py`의 `create_book` 로직을 수정하여 확장된 데이터를 올바르게 DB에 삽입(`INSERT`)하도록 개선.

### C. 프론트엔드 최적화: CSS 모듈화 및 UI 개편
- 300줄이 넘어가던 기존 `style.css`를 전역/홈/검색결과/상세페이지 등 **역할별로 4개의 파일로 분리**.
  - `common.css`: 폰트, 기본 레이아웃 지정.
  - `index.css`: 메인 검색 화면.
  - `results.css`: 검색 결과 카드 및 페이지네이션.
  - `book_detail.css`: 책 표지, 상세 정보, 리뷰 아이템 스타일링.
- 각 HTML 템플릿(Jinja)에서 필요한 CSS만 로드하도록 `<link>` 태그 분리 및 최적화.

## 2️⃣ 트러블슈팅 (Troubleshooting)

### #sqlite3.OperationalError: no such column
- **현상:** `models.py`에 새로운 컬럼(`publisher` 등)을 추가하고 앱을 실행(검색)했을 때 `500 Internal Server Error` 발생. 서버 로그에 `OperationalError` 기록.
- **원인:** SQLAlchemy의 `Base.metadata.create_all`은 애플리케이션 시작 시 DB 파일(`sql_app.db`)이 없을 때만 전체 테이블을 새로 만듦. 이미 존재하는 테이블에 스키마 변경 사항(새로운 컬럼)을 자동으로 마이그레이션(Migration) 해주지 않기 때문에 발생한 불일치 에러.
- **해결 방안 정리:**
  1. **초기화 방식 (채택):** 현재 개발/MVP 단계이므로 기존 `sql_app.db` 파일을 삭제(rm)하고 서버를 재기동하여 새로운 모델에 기반한 테이블을 완전히 새로 생성함. (가장 신속한 방법)
  2. **수동 ALTER 방식:** `sqlite3 sql_app.db "ALTER TABLE books ADD COLUMN ..."` 명령어를 통해 DB에 직접 컬럼 추가.
  3. **장기적 대안:** 프로덕션 레벨로 올라갈 경우 **Alembic** 같은 데이터베이스 마이그레이션 툴 도입 필요성 인지.
